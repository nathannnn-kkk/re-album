# 05｜初步技术方案与开发路线

## 1. 技术方案（建议基线）

采用前端优先的静态 Web 应用，先降低部署与隐私复杂度。技术选型是初步建议，初始化仓库前应确认本机 Node 与包管理器版本，并选择维护活跃、许可兼容的稳定版本。

- **应用：** React + TypeScript + Vite。
- **样式：** CSS Modules 或 Tailwind CSS（二选一，MVP 保持单一方案）。
- **路由：** 首页、模板库、编辑器可先用轻量路由；若只做单页可用 URL state。
- **画布：** 当前原型使用原生 Canvas；封面为 1080 × 1080，社交分享图支持 1080 × 1080、1080 × 1350 与 1080 × 1920。派生成品从统一的封面画布渲染，避免为不同输出重复编辑内容。
- **状态：** React state / reducer 管理当前文档；历史栈实现 Undo/Redo；先不引入服务端状态层。
- **素材：** 项目内原创模板配置与缩略图；用户图片用 object URL / 本地解码，导出后释放资源。
- **部署：** 静态托管；不需要用户内容后端。隐私/分析如需加入，先评估最小化原则和告知要求。

### 初步模块边界

```text
src/
  app/             路由、布局、全局状态
  pages/           Home、TemplateLibrary、Editor
  components/      Button、Dialog、Field、TemplateCard
  editor/          canvas renderer、history、export、image handling
  templates/       schema、原创模板定义、校验
  content/         使用说明、版权说明
public/
  templates/       许可清楚的预览资源
docs/
```

## 2. 数据与隐私

- 默认不设置账号、不上传用户图像、不保存云端草稿。
- 不把图片 Data URL、图像像素、用户文字写入日志或分析平台。
- 文件对象使用后释放 object URL；组件卸载时清理画布资源。
- 若未来需要保存/同步，应单独设计用户同意、删除机制、访问控制和隐私说明。

## 3. 开发阶段

### 阶段 0：产品与素材准备

- 固定首发目标、模板方向和首批 3 个原创模板概念。
- 建立素材清单：文件来源、权利人/许可、允许用途、署名要求、日期。
- 画出首页、模板库、编辑器低保真原型。

**完成标准：** 每个首发模板均有原创说明和素材记录；关键流程不依赖艺人版权素材。

### 阶段 1：画布技术验证

- 验证方形及竖版画布、文字排版、图像裁切、缩放预览和 PNG 导出。
- 验证预览与 1080×1080、1080×1350、1080×1920 输出布局一致。
- 确认文件校验、内存清理和常见浏览器支持。

**完成标准：** 技术样例可以在桌面与窄屏操作，导出结果通过人工对照。

### 阶段 2：模板库与快速编辑

- 建立模板 schema、模板卡、编辑器表单与实时渲染。
- 完成图片替换、图片焦点、文字长度处理和重置。

**完成标准：** 至少 3 个原创模板走通“选择—编辑—预览”。

### 阶段 3：自由编辑与导出

- 增加可编辑图层控制、撤销/重做与 PNG 导出反馈。
- 做移动端布局、键盘操作、错误状态与权利提示。

**完成标准：** 核心用户故事 P0 验收标准通过人工检查和自动化回归。

### 阶段 4：作品集验证与迭代

- 进行 5–8 位目标用户的观察式测试。
- 记录任务完成情况、卡点和原话（征得同意，避免记录个人敏感信息）。
- 按严重程度修订流程，并在作品集说明假设、方法与限制。

## 4. 测试标准

### 功能检查

- 模板选择后配置正确；字段编辑、图片替换、图片移除、重置均更新预览。
- 文本极短、最大长度、空值、中文/英文混排和换行均不会不可控溢出。
- Undo/Redo 历史边界正确；重置确认正确。
- PNG 尺寸、背景、字体、裁切和位置符合画布预览。
- 非法格式、损坏图、超限图片和导出失败有错误提示且保留用户状态。

### 兼容与可访问性检查

- 桌面与移动视口；Chrome、Safari 至少各一轮人工检查。
- 完整键盘访问主要流程；焦点顺序合理且焦点可见。
- 表单标签、错误提示、按钮名称和对比度可辨识。
- 缩放页面后仍可操作，移动设备上控件不被遮挡。

### 发布门槛

- 所有 P0 验收标准完成；无阻断级缺陷。
- 模板与字体来源清单完整，页面权利说明与实际处理方式一致。
- 不存在测试数据、私钥、未经授权的艺人图像或歌词文本。
- 构建可重复完成，发布环境不需要收集用户图片。
